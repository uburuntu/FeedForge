# FeedForge v1.0.0

FeedForge v1.0.0 establishes the first stable package compatibility line for
the project's documented C++ source, CMake, and compiler CLI surfaces. It
qualifies the offline checked-decoder and ahead-of-time compiler delivered
through v0.6 without expanding the project into a feed handler or trading
platform. FeedForge remains neither exchange-certified nor production trading
infrastructure.

## Highlights

- Public, documented C++ source APIs are compatible across the 1.x series when
  consumers rebuild with a supported toolchain.
- Installed CMake packages use same-major compatibility. Documented imported
  targets, supported options, and `feedforge_generate()` remain compatible
  throughout 1.x.
- The documented `feedforgec` command, option, exit-status, and diagnostic-code
  categories are automation-compatible throughout 1.x. Human-readable prose
  and generated provenance may become more precise.
- The compatibility policy explicitly makes no C++ binary ABI promise. Rebuild
  consumers and regenerate custom headers when changing FeedForge versions.
- Package, runtime API, schema, pipeline, FFIR, implementation profile,
  conformance bundle, and benchmark evidence contracts remain independently
  versioned.
- Release qualification covers both default non-throwing and explicit
  exception-enabled toml++ compiler configurations, strict C++20 runtime
  configurations, sanitizer and arbitrary-input coverage, all seven libFuzzer
  targets, real vcpkg consumers, deterministic artifacts, and a clean archive
  build/install/consumer path.

## Product surface

The 1.0 package contains:

- the header-only strict C++20 `FeedForge::runtime`;
- the C++23 `FeedForge::compiler` and `feedforgec` host tool;
- deterministic schema and pipeline validation, FFIR lowering, and generation
  of self-contained checked C++20 decoders;
- one-shot and caller-buffered chunked Nasdaq BinaryFILE replay with explicit
  complete, incomplete, stopped, and error outcomes;
- committed all-message and order-event generated pipelines for Nasdaq
  TotalView-ITCH 5.0;
- independently reviewed protocol fixtures and a separately transcribed
  23-message differential oracle;
- deterministic synthetic conformance-bundle tooling and a checkout-scoped
  vcpkg overlay; and
- benchmark contract 2.0.0 with 16 deterministic correctness cases and
  content-addressed qualification evidence tooling.

## Compatibility

The package and generated-header identity are `1.0.0`. Runtime API epoch 1 and
revision 0 are unchanged. Schema, pipeline, and FFIR format versions remain 1;
`portable_checked.v1` remains the only implementation profile. The synthetic
conformance bundle remains format version 1. Benchmark contract 2.0.0 remains
an independent evidence format and does not change runtime decode semantics.

A non-`EXACT` CMake request for a compatible 1.x package can accept a newer 1.x
release that is at least the requested version. It cannot accept 0.x or a later
major version. Generated headers still enforce their runtime API epoch and
minimum revision at compile time. Custom headers generated by v0.6 that require
epoch 1, revision 0 remain compatible, but regeneration is recommended so
compiler provenance records v1.0.0.

The 1.x source policy covers documented installed C++ headers and targets. It
does not cover undocumented implementation details, test helpers,
source-tree-only targets, compiler or standard-library ABI, or FFIR as an
interchange format. Additive APIs and diagnostics may appear in minor releases;
correctness fixes may reject input that was previously accepted contrary to a
published format or protocol rule.

## Toolchains

The runtime and committed generated headers remain strict C++20. Linux
release-blocking minimum jobs exercise GCC 11 and Clang 14 with the host
compiler disabled. `feedforgec` requires C++23 library support and is qualified
on current GCC, Clang 18 with libc++ 18, AppleClang on the macOS 15 arm64 image,
and the MSVC and ClangCL toolsets on the Windows 2022 image. This replaces the
unproved numeric GCC 13.2 and Clang 17 host-compiler floor claims with the
configurations the release matrix actually exercises. Native MSVC retains an
explicit 19.38 configure rejection bound, but exact 19.38 is not a
release-matrix job.

CMake 3.25 is the declared configuration floor. Minimum runtime/generated jobs
pin CMake 3.25.2 through configure, build, CTest, install, and an external
consumer. A full exception-enabled compiler job also pins 3.25.2 through the
project build, CTest, and canonical generated-byte check. Other platform jobs
use their runner-provided CMake. Shared presets require Ninja. Python 3.11 or
newer is required only for conformance-bundle, benchmark, and release artifact
tooling. The core runtime has no external runtime dependency.

## Qualification

The final v1.0.0 candidate must pass the full Debug and Release suites, generated
byte checks, strict runtime-only and no-exceptions/no-RTTI gates, Clang
ASan+UBSan, the full compiler suite with both supported toml++ exception ABI
settings, allocation tests, Python conformance and benchmark mutation tests, and
all seven standalone arbitrary-input tests. All seven libFuzzer targets run
under ASan+UBSan with their exact source, corpus, toolchain, duration,
executions, and artifact outcome recorded.

Packaging qualification uses the pinned real vcpkg overlay for runtime and
compiler consumers. Deterministic `.tar.gz` and `.zip` source assets are each
extracted into a clean directory, configured, built, tested, installed, and
consumed from an external CMake project. Locally reproduced assets and
`SHA256SUMS` are compared byte-for-byte with fresh downloads from the published
release.

The tagged commit must have release-blocking `C++ security analysis`,
`CI required`, and `Fuzz required` checks green for that exact SHA. Evidence
from another commit, a different archive, or only the individual child jobs is
not release evidence.

## Limitations

- FeedForge consumes caller-provided Nasdaq BinaryFILE bytes. It provides no
  live networking, packet recovery, sequencing, capture service, order-book
  reconstruction, strategy logic, database, or operational trading controls.
- The package is not exchange-certified. The 1.0 compatibility designation is
  not a production-readiness, latency, throughput, or operational-safety claim.
- The public benchmark corpus is synthetic and does not model production
  message frequencies or network packetization. v1.0 adds no new numeric
  performance claim; the retained v0.6 baseline keeps its exact host,
  toolchain, corpus, and uncertainty context.
- The vcpkg overlay remains checkout-scoped rather than a registry release. Pin
  both source and vcpkg revisions when reproducing package evidence.
- No binary ABI compatibility is promised. Rebuild all consuming objects after
  a FeedForge update, including patch updates.
